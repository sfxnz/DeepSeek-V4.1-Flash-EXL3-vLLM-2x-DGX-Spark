#4  Lever: DSV41_NCCL_EAGER_TWIN=1 (docker/patch/nccl_eager_twin.py), default off
    Mechanism read in nccl 2.30.7 source (github tag v2.30.7-1):
      init.cc 2066-2076: NCCL_GRAPH_MIXING_SUPPORT=0 -> graphUsageMode 0; strongstream.cc:
      mixing == (graphUsageMode == 2) is the only switch. With mixing on, each captured collective
      adds an external serialEvent wait at the head of NCCL's device/host capture chains and an
      event-record node per collective (recordEventOnStream), and an eager launch on a comm with
      graph plans may be pushed through a host task behind the graph's host nodes
      (enqueue.cc ncclLaunchPrepare: persistentRefs + cudaEventQuery(hostStream.serialEvent)).
      With NCCL_CUMEM_ENABLE=0, runtimeConn is off (init.cc 1552): every ring/tree connection is
      made in ncclCommInitRank, so a comm first used inside a capture needs no runtime connect.
    Design: the TP CudaCommunicator gets a second PyNcclCommunicator (twin) built right after the
      stock one; pynccl_comm becomes a router that sends a call to the stock comm only when the
      stream it launches on is capturing, else to the twin. Other groups with a PyNccl comm (ep:0,
      unused) get an eager-only guard that raises on a captured call. The patch writes
      NCCL_GRAPH_MIXING_SUPPORT=0 only after the class wrap is in place; NCCL_GRAPH_MIXING_SUPPORT=0
      without the lever is reset to 1 (REFUSED marker). Anchors: CudaCommunicator.__init__ source and
      signature, the full public PyNcclCommunicator API (any unrouted new method disarms), the stream
      parameter position of every routed method.
    Tests: tests/test_nccl_eager_twin.py (21 CPU tests incl. pinned e13 fixtures), full suite 566 OK
      (10 torch-gated skips), render --check 0. In-image CPU check: check_anchors passes on the real
      e13 classes; install() arms, is idempotent, and resets a stray mixing=0.
    Single-GPU smoke on spark2 (twin-smoke/twin_smoke_1gpu.json, pmon: only Xorg/gnome-shell):
      capture predicate true for the capturing current stream, the explicit capture stream and a
      joined side stream, false for an idle stream; eager call -> twin, captured AR + AG -> stock comm;
      500 graph replays each followed by an eager twin AR while the graph is outstanding, NCCL mode 0,
      outputs bitwise equal. (One-rank NCCL comms: no proxy, so this checks plumbing, not the network
      hazard; that is tools/nccl_twin_check.py in the serve window.)
    Expected (modeled from the clean k3 sweep, not yet a serve number): -3.08 ms/step c=1,
      -3.06 ms/step c=2; lower bound = gap + kernel shrink only (~3 us gap + ~2.5 us kernel per call
